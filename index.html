01 / EARN

From a running server
to an earning one.

If you already serve a model with vLLM, llama.cpp or inference-bench, you are most of the way there.

Run an OpenAI-compatible server

Anything that answers /v1/chat/completions over http or https works. It must be reachable from the internet, because private and local addresses are refused.

Add it as a provider

Sign up at app.yalr.net, add your endpoint and set a price per million tokens for each model. Price in sats or in a fiat currency such as USD.

Pass verification

An admin approves the provider, then YALR checks your model against a reference copy. A pass puts you in rotation.

Get routed traffic

Requests for your model are shared across every healthy provider serving it. Each one is billed at your price and credited to your balance.

What you earn. The consumer pays your price. You are credited that amount minus the platform fee, in the currency you priced in. Prices in sats pay out in sats, prices in USD in USD. Withdrawals are not built yet. For now earnings build up as a balance in your account, and you can use it to pay for your own API calls.
02 / TRUST

Why people can use
a stranger's GPU.

Anyone can claim to serve a model. YALR checks, so a cheap smaller model cannot pass as a big one.

Compared with a reference

For each model you price, YALR sends 17 test prompts to both your server and an approved reference provider. Settings are fixed (temperature 0, a set seed, short answers), so the same weights should say nearly the same thing.

Divergence, in plain words

We follow your answer along the reference's own path. Where you part ways, we ask how likely the reference thought your choice was. Different serving software drifts a little. A different model says things the reference rated very unlikely.

Facts and tools

Probes include arithmetic, known facts and tool calls that must parse, and prompt token counts must match the reference.

Hidden probes

Four of the 17 prompts are drawn at random from a hidden pool, so a provider cannot memorise the test.

Safe to connect

Your API key is write-only and never shown again. Endpoints on private networks are refused, checked on every request.

03 / USE THE API

One endpoint.
Many models.

YALR speaks the OpenAI API for chat, images and audio. Pay per token with Lightning or a balance. You can start with an anonymous key bought by invoice, no account needed.

curl · chat completions
curl https://app.yalr.net/v1/chat/completions \
  -H "Authorization: Bearer $YALR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.8-27b-uncensored",
    "messages": [{ "role":"user",
                  "content":"hi" }]
  }'
curl · anonymous key
# Returns a Lightning invoice.
# Pay it and the key is yours.
curl -X POST https://app.yalr.net/v2/lightning/invoice

Routing

Use a bare model name and YALR picks a healthy provider. Full names like org/name are shared round-robin across every provider serving them.

Pay how you like

Lightning sats, or a USD balance. Each request is billed at the price of the provider that served it.

Nostr native
